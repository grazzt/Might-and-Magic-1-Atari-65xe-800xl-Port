# Stock 64 KB / 65XE prototype

2026-10-13, branch `65xe`. **Implemented and checked in Atari800 and
AltirraSDL with 64 KB installed.** The ordinary 130XE profile remains available.
The preceding investigation is [64K-FEASIBILITY.md](64K-FEASIBILITY.md).

## Build and play

```sh
python3 port/atari/build.py --65xe
python3 port/atari/build.py --65xe --disks
```

The first command creates `build/atari65xe/mm1.atr`, containing all four sides.
The second creates `build/atari65xe/disks/mm1-disk1.atr` through `mm1-disk4.atr`:
boot disk 1, then swap disks when the game requests sides A–D. Each is an
Atari enhanced-density image that fits a 1050. Use an XL/XE emulator with
**64 KB**, BASIC disabled, and NTSC timing for the checked configuration.
The kernel switches out the OS while playing and restores it for SIO.
Play on copies: the game writes character saves to disk.

The default build starts with the original animated title and tune. SPACE
shows the eight intro scenes; ESC starts the game and its INSERT DISK B prompt.
Use `--no-title` for the earlier direct-to-game behavior. It uses
fixed grayscale pixel roles by default (or a warm palette with `--colour`)
and omits the POKEY effects translator. Text,
artwork, geometry, menus, two original bitmaps and page flipping remain.
Original cell hues and the blue encounter panel are lost; a nonzero pixel
pair formerly assigned black may now be visible. The original SID sequencer
and game rules for ending sounds still execute. Presentation differs; game
rules, RNG, data, input semantics and save payloads are checked against C64.

## How it fits

The old extra 16 KB bank contained presentation support, rather than game
logic. Direct ANTIC mode 4 display removes that bank, the 4 KB conversion
lookup and the full converted screen. Nineteen of the 25 bitmap rows display
from original RAM. The six rows crossing a 1 KB character-set boundary are
copied into two shared 1 KB blocks. DLI changes CHBASE per row; a 128-byte
sequence of character codes supplies all rows through display-list LMSes.

| Main-memory allocation | Bytes | Purpose / lifetime |
| --- | ---: | --- |
| `$9D00–$9FFF` | 768 | Loader, SIO adapter, ROM-font reconstruction |
| `$DC00–$DFFF` | 1,024 | OS zero-page save, input, interrupts, direct renderer |
| `$FF50–$FFFF` | 176 | Stand-in chips, text display list, state, vectors |
| Existing presentation routines / entries | 156 | Three shortened colour/bank routines, publication wrappers and tables |
| `$CC00–$CFFF` | 1,024 | Graphics: rows 3/6/9; text: reordered OS font |
| `$D800–$DBFF` | 1,024 | Graphics: rows 12/19/22; text: completed text snapshot |
| `$0100–$017F` | 128 shared | SIO sector staging or one ROM-font half-page |
| `$2000–$3F3F` | 8,000 retained | Upper bitmap; `$2000–$34FF` also hosts game overlays |
| `$E000–$FF3F` | 8,000 retained | Lower bitmap; combat entry also backs up resident code here |

This is an allocation/lifetime table, **not an additive total**: game buffers
and stack staging already existed and have alternate owners. Resident kernel
segments now occupy 2,124 bytes including 156 borrowed bytes. No extended
segment, converted screen or lookup table is loaded for gameplay. `layout*.json` records
all allocations and build-time overlap/fit checks. The four-disk loader has
only **2 free bytes**, and the display segment **7**; future features need a
fresh budget. Disk 1 uses 440 sectors, disk 2 795, disk 3 749 and disk 4 743,
within 1,029 available data sectors each.

The full two-bitmaps scheme is essential. Before combat, EN backs up
`$4000–$5EFF` to `$E000–$FEFF` (7,936 bytes), then CM restores it. Reclaiming
lower-bitmap padding for permanent code corrupts resident state. The
`$0800–$0AFF` range is six live party records, also unavailable.

## Publication, SIO and patch contracts

`profile65.py` checks literal original bytes before patching colour stores in
resident, startup, GO and EN code. Indirect writers were traced and classified
with `tools/atari65_colour_writes.py`; [the retained audit](../test-artifacts/64k/colour-writers.json)
identifies their modules, PCs and destinations. Drawing and pointer arithmetic
remain. Three compact routines at `$1C18`, `$C276` and `$C40D` retain their
non-colour outputs and loader contracts, supplying room for tables/font code.
The assembled replacements are checked for immutable code at every mark.

Text and graphics DMA are disabled during ownership changes and SIO. A new
snapshot or all six copy rows completes before VBI publishes it. The text
font is reconstructed from OS ROM using a thunk below the ROM, eight 128-byte
stack-page copies, NMI disabled and a stack guard. The current text font must
match the emulator's captured OS font byte for byte. A stack below `$90`
at the guard fails safely instead of overwriting the active stack; none of
the checked scenarios trips the guard.

The faster renderer exposed an old timing heuristic: a combat pause could
consume the key-change flag, then print a prompt and reach GETIN within two
frames, leaving an old snapshot. Small entry wrappers force one publication
on each normal key wait and both pause paths. Their stack, input registers,
flags and the original wait/pause loops are preserved. They use an unused
resident Y/N-reader copy at `$C91A–$C92B`. Ordinary idle polls keep the old
heuristic and do not continuously copy/blank the screen. While publication is
busy, VBI holds the game clock and disables row DLIs; equality-based pauses
must not miss their target tick.

The host reference executes the presentation replacements but keeps its
original wait/pause entries: a native wrapper would write an Atari flag at a
C64 CIA address. Captured entry code bytes are normalized to the assembled
wrappers, whose native immutability is checked separately. Each reference's
comparable events and disk hashes must also equal a separate unmodified
Oracle replay. No original source disk is edited.

Two presentation/input differences are explicit in comparisons:

- `$CC00–$CFFF` now holds crossing rows or the font, verified independently.
- `$028E` is the released CTRL input latch. The Atari key-up routine and C64
  KERNAL IRQ clear it at different times after scripted input; shorter colour
  routines can leave the reference's value at 4 for an extra interrupt.
  Settled native marks must contain 0. CTRL is delivered before GO `$78A2`
  consumes it; selected party records, gameplay events and saves still match.

All other standing exclusions retain their documented timing/hardware reasons
in `lockstep.py`. Each settled native screen is compared pixel by pixel with
an independent model of the original bitmap or text bytes, and crossing-slot
copies/font bytes are checked directly. Altirra RGB levels are normalized to
pixel roles with artifact colours disabled; geometry and every pixel are
still compared. Altirra also gets a paused PORTB bank alias probe: writes to
`$4000` through a purported alternate bank must alias main RAM on 64 KB.

## Remaining work

This is a useful playable 64 KB prototype, not proof of the entire game on
physical hardware. All existing scenarios pass; unexplored areas, spells and
rare stack depths remain outside that coverage. PAL, real 65XE/1050 and DOS
boot variants have not been checked. The temporary title has POKEY music; in-game POKEY effects remain omitted.

Next: validate PAL/hardware and broaden game coverage, improve per-area
pixel-role palettes, and consider a smaller in-game sound translator. The
original title now uses temporary startup RAM as described below. Full original cell-colour fidelity would
need asset recoding or a different renderer; it does not fit by adding back
the former bank. Keep the working grayscale baseline while measuring each
presentation improvement against its actual resident/linker cost.


## Town flicker and colour follow-up — 2026-10-13

The previous 9-frame prototype blanked the display during every GETIN copy.
Captured movement/turns include one or two entirely black frames. More subtly,
the original game flips its mode then immediately clears the old bitmap, while
the prototype waited until GETIN to update CHBASE: the old displayed view was
being erased before publication. Settled pixel tests did not detect transients.

The mode-store entry at `$1C13` now preserves CPU registers/flags, refreshes,
and waits for VBI before returning to the game's hidden-page clear. During
bitmap-to-bitmap updates DMA and row DLIs remain enabled; a busy bit holds the
game clock independently of visibility. Font/text ownership changes and SIO
still blank. The pure colour-copy footer at `$0E1F` is shortened with identical
A/XY/pointer/flag results to provide helper space. Unused stand-in VIC ranges
supply the flip return code and 25-byte CHBASE array; the complete static game
hardware inventory rejects any user of these reserved bytes, including indexed
accesses requiring a new bounds audit. No added bank or gameplay-data buffer.

**Measured:** movement and both turns now have zero black frames in the
Atari800 frame captures. The old raw bitmap is no longer erased before publication. Copies still update shared crossing-row glyphs over more than one
frame, so brief horizontal tearing remains: this is a reduction of flicker,
not a claim of perfectly atomic frames. Movement is 12 NTSC frames, turns
11/12 (about 200 ms walking). Settled screens, state and saves continue to
match. Evidence: `test-artifacts/64k/flicker-before/`, `flicker-after/` and
`flicker-gameplay/` (all 21 scenarios / 257 checkpoints).

**Colour is possible without extra RAM.** `build.py --65xe --colour` selects
GTIA pixel roles black / dark brown / gold / white (`$00/$24/$28/$0E`) instead
of grayscale. Text-mode menus remain white. Only two immediate operands change;
resident sizes and the 64 KB allocation ledger are identical. This is a fixed
palette, not the original C64 colours selected separately for every cell.
Colour verification includes town services, outdoors, side D and save/reload
(65 Atari800 checkpoints), plus ordinary keyboard play and the same zero-black
frame assertion. Both emulators pass colour serial save/cold reload (27 marks each), and
the full updated regression suite passes **120 tests**. Logs are retained
with the follow-up evidence.

```sh
python3 port/atari/build.py --65xe --colour
python3 port/atari/speed65.py --transients --assert-steady --out test-artifacts/64k/flicker-after
python3 port/atari/check65.py --out test-artifacts/64k/flicker-gameplay
```

Further improvement: colour by area or horizontal region needs a small amount
of code/palette state, rather than the old 16 KB converter bank. Matching all
C64 cell hues would require artwork remapping or another renderer. Fully
atomic page flips also require separately staged crossing-row data or carefully
scheduled copying; simply removing DMA blanking exposes tearing, and simply
waiting for VBI before starting a 1,920-byte copy does not make it fit inside
vertical blank. Keep testing transient frames, rather than settled screens only.


The rebuilt grayscale single image is `build/atari65xe/mm1.atr`; its four disks
remain in `build/atari65xe/disks/`. A separate non-test colour preview is
`build/atari65xe/mm1-colour.atr`, with four disks in `build/atari65xe/colour-disks/`.
Use fresh copies for playback; all paths and hashes are recorded in
`test-artifacts/64k/flicker-playable-images.json`.


## Original C64 intro restored on 64 KB — 2026-10-13

Disk A can do more: it already contains the original intro assets. The build
now runs the **original C64 title program** before loading the resident game,
with only its existing hardware operand redirections. Both animated title
frames display directly, in colour. SPACE shows the eight original scenes;
ESC returns to boot, loads the game and asks for disk B. The title repeats
with its tune after scene 9, as on the C64. The tune's three original voices
are translated to POKEY, using the existing pitch/envelope method. The melody
is original; POKEY waveforms approximate SID timbres.

The previous permanent memory shortage does not apply before the game loads.
The new stage and its music tables are about 2.6 KB at `$8000`. Original title
code uses `$4000–$4F7F`, a converted scene uses `$5000–$73FF` (9 KB), and boot
parks temporarily at `$A000–$BBFF`. The direct-frame crossing buffer at
`$1400–$1BFF` becomes a 600-byte palette/mapping plan during scenes. These
owners never overlap in time. `layout*.json` records the startup-only ranges.
All these temporary bytes are overwritten by the normal startup snapshot and
resident loads when ESC is pressed. **The permanent kernel is byte-identical
with and without the intro; no extended bank or extra gameplay allocation.**

Scene colour plans are derived at build time from the original Oracle's
artwork and the independent existing row-colour policy, including portrait
frames. They contain 100 row-register values and 500 packed cell-role mappings.
At runtime the original program still draws the bitmap and its colour matrices;
a 256-byte nibble table converts those bytes using the plan. Original bitmap
and colour metadata remain unchanged. This avoids bringing the permanent
130XE converter bank back into the 64 KB build. Plans are read from disk A
as needed and discarded with the stage. Disk A now uses **468 of 1,029 data
sectors**; disks B/C/D remain 795/749/743.

**Checked in Atari800 and AltirraSDL at actual 64 KB:** both title frames match the original
pixel for pixel; all eight scenes match the independently prepared colour
model and retain original bitmap/colour metadata; title loop, ESC, kernel
restoration, OS font reconstruction, disk B swap and options menu work.
A four-disk run matches 1,899 music ticks in 1,900 sampled frames (two late
frames); the
single-image and Atari800 serial tests allow the same small interrupt-timing
allowance as the existing 130XE checks. AltirraSDL also checks every frame and
scene pixel, loop, ESC and disk B handoff through unpatched serial SIO. All 21 gameplay scenarios / 257 checkpoints
pass after the title, including cold save reload. The startup memory test
compares every permanent kernel segment with the no-title build. The full
regression suite passes 124 tests; all four intro tests were rechecked after
the final interrupt changes. Ordinary keyboard input on the non-test warm
image also reaches a scene, exits to the prompt, selects a six-character
party, enters town and walks forward. Download hashes and sector use are in
`test-artifacts/64k/title-playable-images.json`.

```sh
python3 port/atari/build.py --65xe --disks             # title, then game
python3 port/atari/build.py --65xe --disks --colour    # same intro, warm game palette
python3 port/atari/build.py --65xe --disks --no-title  # skip intro
python3 port/atari/title65_check.py
python3 port/atari/title65_check.py --single --sio
python3 port/atari/title65_check.py --altirra --sio
python3 port/atari/check65.py --title
```

The `build()` APIs retain `title=False` as their test-friendly default; the
CLI includes the title unless `--test`/`--no-title` is supplied. `--title`
works with test mode. Evidence is retained under `test-artifacts/64k/title-*`.
The existing gameplay tearing, palette limits, omitted in-game effects and
untested PAL/physical hardware remain unchanged.
